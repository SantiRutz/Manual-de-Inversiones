# AGENTS.md

## Repository shape

- This is a Spanish-language manual repository with a custom Node.js Markdown→HTML generator; there is no `package.json`, lockfile, CI, `npm test`, lint, or typecheck configuration.
- Run commands from the repository root. Node.js is the only required runtime.
- Edit the canonical `manual_parts/*.md` files, not the generated `MANUAL_VALUE_INVESTING_Y_ANALISIS_FINANCIERO_REVISADO.md` or `.html` files. Exception: `manual_parts/parte_38_casos_reales.md` is generated by `tools/casos_reales_render.js` from `tools/casos_reales.js`; never edit it by hand.
- `tools/build_manual.js` is the executable source of truth for the exact 15-part order and output names: `parte_36` (apéndices), `parte_35` (aliases), `parte_38` (casos reales), `parte_37` (protocolo, always last). Do not rebuild by globbing every Markdown file.
- `tools/build_website.js` derives that same canonical order, builds the static multi-page site in `site/`, and bundles a local full-text search index. Site styles/behavior are sourced from `tools/site_template/`; do not edit generated `site/` output by hand.
- Historical draft folders, audit reports, and migration/debug scripts were removed; do not recreate alternate canonical parts. `tools/build_manual.js` remains the only source of build ordering.
- Design specs live in `docs/superpowers/specs/`; the 2026-09-29 spec records why the real-cases section exists and the decisions behind it.

## Required workflow

Run in this order after changing canonical Markdown:

```powershell
node tools/build_manual.js
node tools/validate_manual.js
node tools/validate_html.js
node tools/verify_reviewed_numbers.js
node tools/canonical_cases.js
node tools/dcf_sensitivity.js
node tools/scan_master.js MANUAL_VALUE_INVESTING_Y_ANALISIS_FINANCIERO_REVISADO.md
node tools/scan_question_artifacts.js MANUAL_VALUE_INVESTING_Y_ANALISIS_FINANCIERO_REVISADO.md
node tools/build_website.js
node tools/build_apk.js
node tools/validate_website.js
```

- Run `build_manual.js` before `validate_manual.js` and `validate_html.js`; run `build_website.js` before `validate_website.js`. The Markdown validator checks source/master parity, the 34 chapter numbers, required formulas, terms, and known artifacts.
- `validate_html.js` checks the generated standalone HTML, converted math blocks, checkboxes, tables, and character artifacts.
- `validate_website.js` checks the generated 39-page static site (38 search-index documents), local links/anchors, offline assets, full-text search index, and formula blocks. It also asserts the cover plate's price/IV/MoS match `tools/casos_reales.js`.
- For a focused Markdown check, pass an alternate master path to `validate_manual.js`; for a focused HTML check, pass a path to `validate_html.js`.
- If chapter 30 inputs change, update the expected fixtures in both `tools/canonical_cases.js` and `tools/verify_reviewed_numbers.js`, then run both scripts.
- If a real case changes, edit only `tools/casos_reales.js`: `verify_reviewed_numbers.js` recomputes terminal flow, TV, bridge, per-share IV and MoS from the module (no separate fixtures), and `validate_website.js` catches plate/module drift. `placaId` selects which company the cover plate shows.
- The reviewed Markdown/HTML and the `site/` folder are generated deliverables; edit canonical parts or `tools/site_template/`, then rebuild rather than patching outputs by hand.

## Android APK and deployment

- `android/` holds a dependency-free WebView reader (`MainActivity.java`, manifest, adaptive icon). `tools/build_apk.js` rebuilds `site/`, then packages it with the installed JDK 17 and Android SDK (aapt2 → javac `--release 8` → d8 → zipalign → apksigner); no Gradle, no network.
- The APK requests no permissions: the whole site ships in `assets/site` and external links open in the system browser. Output: `dist/manual-inversion.apk` (ignored) plus the published copy `site/descargas/manual-inversion.apk`, which the home page links to (`validate_website.js` fails if it is missing). The download folder is excluded from the APK itself.
- Rebuild the APK whenever `site/` changes so the downloadable copy is not stale. It is signed with `~/.android/manual-inversion.jks` (override with `APK_KEYSTORE` / `APK_KEYSTORE_PASS`); keep that key outside the repo — updates must use the same key.
- Inside the app the user agent contains `ManualInversionApp/`; `site.js` adds `html.is-app`, which hides `.web-only` elements. The app overrides `window.print()` with Android's print service and mirrors the light/dark theme onto the system bars.
- Vercel serves `site/` as-is (`vercel.json`: no build, `outputDirectory: site`).

## Content invariants

- Keep the final 30-minute/1-hour/3-hour protocol in `manual_parts/parte_37_protocolo_tiempos.md`, after the canonical appendices, aliases, and casos reales; the published document must retain 34 chapters and that final section.
- All company cases, prices, returns, and portfolios are fictional in chapters 1–34 and appendices. Preserve the stated case cutoff (31 December 2025) and editorial date (24 September 2026). Only `parte_38_casos_reales.md` contains real market data from published filings; each company declares its exercise, audit status, source and consultation date. Do not add current market data without an explicit request and dated sources.
- Real-cases module conventions (`tools/casos_reales.js`): all money in MILLIONS of the stated currency, shares in MILLIONS; `resultadoNeto` is attributable to the parent (minorities grouped into tax — document it in `normalizaciones`); missing data is `null`/`n/d`, never a silent estimate; calibrate projected `flujos` so the conservative IV stays positive (`verify_reviewed_numbers.js` asserts `ivBajo > 0`). Banks use `metodo: 'FCFE/Ke'` with `ke`/`keDelta`, `flujos` as distributions, `deudaNeta: 0`, and no EV bridge — see `esBanco()` and the JPMorgan entry.
- Keep the cash-flow conventions distinct: historical `CFO − CapEx` is apalancado FCF; FCFF is discounted with WACC to EV; FCFE is discounted with `K_e` to equity. Do not mix flow definitions or denominators.
- Use `MoS = (IV − price) / IV` (equivalently `1 − price/IV`); never label `1 − IV/price` as margin of safety. A negative MoS (price above a positive IV) is shown as-is for real cases; only a non-positive IV has no expressible percentage.
- Match DCF flow and rate (`FCFF`/WACC or `FCFE`/`K_e`), and do not multiply an already indexed terminal flow such as `FCFF_(n+1)` by `(1+g)` again.
- Distinguish historical ROIC/WACC (EVA) from incremental ROIC and project NPV; keep the EV→Equity bridge, table master, glossary, aliases, and appendices consistent.
- Generated material must not contain Cyrillic, CJK, or Hangul characters (`validate_manual.js` rejects them); write foreign line-item names in Spanish.
- Both HTML generators expect closed `\\\[ ... \\\]` math blocks; run `validate_html.js` and `validate_website.js` after formula/parser changes.

## Site theme and cover plate

- Default theme is dark (`data-theme="dark"`, initial value in `tools/site_template/site.js`); the stored preference key is `manual-theme` — a returning visitor's explicit choice always wins, so only the first paint changes.
- Accent split: teal (`--teal`/`--teal-dark`) for action and navigation (primary button, links, progress bars, active nav, table headers); gold stays a data flourish only (formula blocks, MoS figure, `DESCUENTO` label, table top rule, `h1` underline). Do not promote gold to new interactive roles.
- The cover plate SVG is computed in `plateMarkup()` (`tools/build_website.js`) from the module — never hardcode its numbers. It needs `prefers-reduced-motion`-safe static output and a one-column `.plate-read` fallback under 520 px.
- The `@media print` block in `site.css` must redefine every theme token (dark values leak onto white paper otherwise).
- Print is a formal A4 edition: `@page` margin boxes add running heads and `page / pages` numbering (Chromium; other browsers ignore them), `.print-masthead` / `.print-colophon` are emitted by `pageShell()` and are hidden on screen, and the home page prints as a cover.
